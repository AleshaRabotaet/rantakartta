# Rantakartta

Карта туристического жилья у небольших хозяев Финляндии (коттеджи, B&B, глэмпинг, палатки).
Данные собираем с витрин на движке Johku, бронирование всегда на сайте хозяина.
Пет-проект одного разработчика: простые решения важнее «правильной» архитектуры.

## Стек
- Python 3.11+: `stays/` — парсер, геокодинг, сборка данных. Зависимости в `requirements.txt`.
- Фронтенд: статический `web/index.html` (Leaflet + markercluster с cdnjs), данные в `web/data.js`.
  Без сборщика и фреймворков, пока объектов меньше ~5000.
- Хостинг: GitHub Pages из папки `web/`. Обновление данных: `.github/workflows/update.yml`.

## Команды
- Тесты: `python -m pytest -q`
- Быстрый прогон одной витрины: `python -m stays.build --source visitpuumala --limit 5`
- Полный прогон: `python -m stays.build`
- Пересобрать только web/data.js: `python -m stays.build --export-only`
- Посмотреть карту: `python -m http.server -d web 8000` и открыть http://localhost:8000

## Структура
- `stays/models.py` — `Listing`, списки допустимых `TYPES` и `PRECISIONS`.
- `stays/johku.py` — обход раздела и разбор страницы объекта **по текстовым меткам** (локаль en_US).
- `stays/geocode.py` — Nominatim с кэшем `data/geocode_cache.json`; фолбэк на точку хозяина/района; `spread()`.
- `stays/build.py` — CLI сборки.
- `sources.yaml` — витрины, точки хозяев, центр района.
- `data/listings.json` — все объекты (коммитится). `web/data.js` — генерируется, руками не править.
- `docs/` — видение, решения, источники, схема. При принятии решения дописывай `docs/decisions.md`.

## Правила парсинга (обязательно)
- Пауза между запросами не меньше 2 с (`REQUEST_DELAY_S`), честный User-Agent с контактом.
- Перед добавлением новой витрины проверь её robots.txt.
- Не копируем описания и фото: храним заголовок, цену «от», тип, места, адрес, теги, ссылку на превью и URL.
- Разбор по меткам, не по CSS-классам. Новую метку сначала добавь в тест-фикстуру.
- Точность координат всегда честная: `exact` только при геокодинге адреса с улицей.

## Как работать
- Меняешь парсер — сначала фикстура и тест в `tests/`, потом код. Реальные страницы сохраняй в `tests/fixtures/`.
- Не трогай `web/data.js` и `data/listings.json` руками — только через `stays.build`.
- UI на русском. Цвета и шрифты — CSS-переменные в начале `web/index.html`, новые не придумывай без нужды.
- Маленькие коммиты, одно изменение — один коммит.
- Новая фича — всегда отдельная ветка, залинкованная с issue на GitHub: один issue —
  одна ветка — один PR с `Closes #<номер>` в описании.
