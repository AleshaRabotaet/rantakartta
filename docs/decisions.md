# Журнал решений

Формат: дата, решение, почему. Новые сверху.

- **2026-09-25** Мультиязычный интерфейс (issue #16): словарь строк `STRINGS = {fi, sv, en}`
  в `web/index.html`, без `ru` — issue просит явно три языка, старое правило `CLAUDE.md`
  «UI на русском» снято. Определение языка по приоритету: `#lang=` в `location.hash` →
  `localStorage["rantakartta:lang"]` → первый поддерживаемый subtag из
  `navigator.languages`/`navigator.language` → фолбэк `en`. Переключатель — три кнопки
  `.chip` в `.head` (переиспользуют существующий стиль фильтров, новый CSS не понадобился).
  `lang` — ещё один ключ в `location.hash`, наравне с `q`/`type`/`tags`/`max`/`exact`/`id`
  (см. запись про формат hash-ссылки ниже); в отличие от остальных ключей пишется в hash
  всегда (даже дефолтный), потому что языка без значения не бывает — значит `syncHash()`
  больше никогда не очищает hash полностью. `TYPES`/`TAGS` во фронтенде разделены на
  язык-независимые `TYPE_COLORS`/`TAG_KEYS` (цвета, порядок) и подписи через словарь.
  Переводы FI/SV/EN — черновые (не носитель языка), стоит вычитать при возможности.
- **2026-09-25** Обход витрин переведён с парсинга ссылок одной HTML-страницы раздела
  (`parse_listing_page`) на `googlesitemap.xml` (issue #6). Причина: у части витрин раздел
  жилья разбит на несколько страниц по типу объекта (Rauhanlaakso — 5, Nyyssänniemi — 3),
  и часть объектов/разделов существует только на fi_FI, не будучи никогда переведена на
  en_US (Tervarumpu — целый район Verla, 15 объектов; Visitpuumala — 2 мерчанта, 9 объектов;
  Purolomat — вообще без en_US). Sitemap есть у каждой проверенной витрины Johku и отдаёт
  все реальные товарные URL сразу, независимо от того, что хозяин добавил в навигацию.
  `sources.yaml: section_url` (строка) → `section_paths` (список URL, может включать
  fi_FI-only разделы вперемешку с en_US). Старый анкор-парсинг оставлен как фолбэк на
  случай отсутствия sitemap.
- **2026-09-25** `stays/johku.py` разбирает финские метки (`LABELS_FI`) наравне с
  английскими — единый алиас-словарь на канонический английский ключ, весь код ниже
  (`parse_product`, geocode) остаётся англоязычным. Причина — та же, что выше: часть
  Johku-витрин никогда не переводит часть каталога на en_US. Метки те же самые, что и на
  en_US, просто на другом языке — страница устроена идентично.
- **2026-09-25** Дедуп при обходе — сначала по slug (одинаковый URL-хвост на двух
  локалях — тот же объект), затем по `image` после парсинга (issue #6): одна и та же
  карточка на fi_FI иногда получает совсем другой, не машинно-переводной slug
  (Kalliola/`okkola-kalliola` vs `okkola-https-www-okkolanlomamokit-com-en`), но фото
  всегда одно и то же — оно и стало вторым, более надёжным признаком дубля.
- **2026-09-25** Региональные «зонтичные» Johku-порталы (iisalmijatienoot.fi,
  lhgeopark.johku.com) НЕ подключены в issue #6: их раздел жилья — SPA на Nuxt, карточки
  подгружаются JS-запросом к внутреннему API, ни в HTML, ни в `googlesitemap.xml` нет ссылок
  на конкретные товары. Нужен реверс API или headless-браузер (Playwright уже есть в
  зависимостях, но для UI-тестов, не для обхода) — отдельная фича со своими тестами и
  фикстурами, не в рамках этого issue.
- **2026-09-25** `stays/johku.py: USER_AGENT` — плейсхолдер `CHANGE_ME@example.com` заменён на
  `bet4lulz@pm.me`. Nominatim отклонял такой контакт («Access denied»), а `geocode.py` не кэширует
  сетевые ошибки — баг был незаметен, ни один объект с адресом с улицей не получал `exact` ни на
  одной витрине. Закрыто тестом в `tests/test_johku.py` (issue #3).
- **2026-09-25** Для объектов Johku-витрин без адреса с улицей, если OSM их не картографирует
  (частные домики обычно не картографированы) — доверяем `latitude`/`longitude` из schema.org
  JSON-LD на странице продукта напрямую, без сверки через Overpass (в текущем облачном окружении
  `overpass-api.de` недоступен по сетевой политике). Проверено на независимом сравнении:
  `visitpuumala:ukonhonka-latukka` — geocode по адресу и JSON-LD совпали в пределах ~5 м (плюс
  более ранняя ручная сверка `sammaltupa` у Tervarumpu, ~10 м). Если JSON-LD для разных объектов
  одного хозяина совпадает один в один (замечено у 3 домиков Mannilanniemi) — это не индивидуальная
  точка, override не добавляем, честно остаётся `merchant`. См. `docs/sources.md`, раздел Visit
  Puumala (issue #3).
- **2026-09-25** Фильтры и выбранный объект — в `location.hash`, ключи `q`, `type`
  (CSV), `tags` (CSV), `max`, `exact`, `id`; пишутся через `history.replaceState`
  (без записей в историю браузера), пустые/дефолтные поля в hash не попадают.
  Формат — публичный API ссылки, менять обратно несовместимо нежелательно.
- **2026-09-25** Отчёты формы «Неточность?» копятся комментариями в одном issue-коллекторе
  (#32, `COLLECTOR_ISSUE_NUMBER` в `netlify/functions/report-issue.js`), а не создают
  отдельный issue на каждое обращение. Причина: MVP, ожидаемый объём небольшой — один тред
  проще просматривать, чем плодить issues на каждую жалобу. Пересмотреть, если поток
  вырастет.
- **2026-09-25** Форма «Неточность?» в попапе шлёт `fetch` на Netlify Function
  (`netlify/functions/report-issue.js`), которая создаёт GitHub Issue токеном из секрета
  `GITHUB_TOKEN` (fine-grained PAT, только Issues: Write на этот репозиторий). Причина:
  ссылка на `github.com/issues/new` требовала от пользователя логина в GitHub — это
  отсекало часть жалоб на неточности. Прямой вызов GitHub API с клиента невозможен: токен
  на статическом GitHub Pages нельзя спрятать. Netlify выбран как бэкенд, потому что у
  автора уже есть аккаунт; сам сайт остаётся на GitHub Pages, Netlify используется только
  ради Functions. Рейт-лимитов и капчи пока нет (только honeypot-поле) — добавить при
  реальном спаме.
- **2026-09-25** Аналитика — GoatCounter (без cookies, без баннера согласия): pageview
  автоматически, плюс события клика «Открыть у хозяина» (с id объекта), включения
  фильтра типа/тега и выбора объекта из списка. Код счётчика — константа
  `GOATCOUNTER_CODE` в начале `<script>`, значение `"rantakartta"` —
  зарегистрированный аккаунт на https://rantakartta.goatcounter.com/.
- **2026-09-25** Сетевой слой парсера (`stays/johku.py`) — `httpx` вместо `requests`. Johku
  (Nuxt) отдаёт HTTP 103 Early Hints перед ответом, stdlib `http.client` его не пропускает и
  получает пустое тело; `httpx` 1xx обрабатывает корректно.
- **2026-09-25** `sources.yaml`: `merchant_name` — имя хозяина на уровне витрины для источников без
  `merchants` на объект (Tervarumpu — хижины нацпарка, не у частных хозяев). `overrides: slug → {lat, lon}` —
  ручные координаты в обход геокодинга, приоритет выше адреса и точки хозяина, precision всегда `exact`.
  Используется, когда у объекта нет адреса с улицей и нет точки хозяина, но координаты известны точно
  (например, POI в OpenStreetMap).
- **2026-09-25** Подложка OSM standard вместо CARTO: CARTO с августа 2026 требует ключ.
  При росте трафика перейти на MML или CARTO с ключом.
- **2026-09-25** Фронтенд без сборщика: один HTML + data.js. Причина: мало данных, быстро менять,
  хостинг на GitHub Pages. Пересмотреть при >5000 объектов.
- **2026-09-25** Парсер Johku разбирает страницу по текстовым меткам en_US, а не по CSS.
  Метки одинаковы на всех витринах движка.
- **2026-09-25** Три уровня точности координат: exact / merchant / area. На карте неточные
  точки с пунктирной рамкой. Объекты с одной точкой разводятся по спирали (`spread`).
- **2026-09-25** Из раздела жилья исключаем подарочные карты и многодневные каяк-туры.
- **2026-09-25** Источники: Johku-витрины сейчас; Visit Finland DataHub для покрытия страны позже;
  Johku API — после ответа Aptual Commerce (письмо Ilkka Lariola).
